## Native execution and authority

Historical isolated private repository: [KoolingMachine/ads-cnb-acceptance-20261027](https://cnb.cool/KoolingMachine/ads-cnb-acceptance-20261027). Its historical runs are fixture evidence only. The current ALNILAM CNB repository, access, source checkout, branch protection, scanner/review execution and artifact download still require fresh readback. A GitHub green check is not a CNB result.

Toolchain preflight in this separate task worktree: PATH resolves RTK `1.0.1`; `rtk verify` passed 151/151 checks but reported the host hook absent, and `rtk run` preserved stderr and exit `7`. PATH resolves CodeGraph CLI `1.0.1`; `codegraph status .` reported uninitialized, and host MCP reported no `.codegraph/` index. The CLI source/channel was not verified as the authorized stable distribution. No tool, hook, setting or index was installed or changed. This worktree does not satisfy the ADS v0.4.2 per-worktree CodeGraph / official full RTK preflight; the separate primary-checkout result is recorded in [Issue #37](https://github.com/Skyline-Gazer/ALNILAM/issues/37).

In the current `.cnb.yml`, `pull_request` runs the official Code Review plugin as an advisory comment and records its JSON; it does not create a required Review status, parse severity, bind the plugin result to a trusted SHA, or block on Critical/Warning findings. The trusted `pull_request.target` pipeline separately validates native PR identity, current source/target refs and merge parents, then runs deterministic consumer CI on the exact merge commit. It does not consume the AI Review JSON. Same-repository source/target identity is required; fork PRs fail closed. Candidate code and its test commands run under an unprivileged UID without `CNB_TOKEN` or Git remotes; only non-secret PR identity metadata is forwarded to trusted receipt writers. After candidate processes are stopped, the gate snapshots artifacts into a Runner-owned tree before validating or archiving them. SCA publication is part of the trusted target pipeline. No claim is made that AI Review findings are a trusted merge gate.

All container references in `.cnb.yml` use observed immutable registry digests. The Playwright manifest list includes amd64 and arm64; the runner explicitly selects amd64. Registry availability is not proof of a CNB pull/launch. Image source, manifest and runtime are recorded separately.

## Measurements and failure evidence

The Node LCOV gate counts only `.mjs` files under `packages/core/src/` and `apps/web/src/lib/`, plus `scripts/site-contract.mjs`, `scripts/upgrade-check.mjs` and `scripts/compose.mjs`. The trusted `source-summary.json` and CNB `.mjs` coverage step consume the same filtered LCOV. This is not whole-application line coverage: it excludes `themes/shirone/src/`, `packages/ui/`, Astro pages, generated code and browser execution; the separate Playwright suite exercises representative rendered behavior but does not report UI line coverage. The earlier P1 baseline was 359/462 lines (77.7056%); the repeat CNB run measured 388/491 Node-source lines (79.0224%) against the 77% minimum. This is whole-selected-source coverage, not changed-line coverage. Missing/empty/test-only reports, mismatched receipt minimums and deliberate coverage reduction have local negative tests; the missing-report native failure was observed.

The browser suite reuses the existing root/nested servers at 390/1440px, captures load/theme/navigation/search/tags/scroll/restoration, console and network errors, and records actual LayoutShift attribution. The session algorithm excludes recent input and starts a new session after a gap greater than one second or duration greater than five seconds. Normal pages are baseline-only until repeated native measurements support budgets. Deterministic reserved-space image/font/lazy/menu/comments/ad/consent/adblock fixtures use a 0.10 ceiling; explicit large shifts must make the same gate fail. FontFace uses an installed local font; no external-font-network result is implied. Lab CLS is not field p75 CLS.

Optional AdSense/GA4/Consent/DKMA/Giscus fixtures use mocks only. Disabled actual product pages must make zero related requests. Mock fixtures check consent, repeated initialization/pageviews, reserved ad/comment geometry and readable articles with blocked requests. They do not implement or claim acceptance of future modules #90–#93, or a live Giscus integration.

LHCI records `numberOfRuns` real measurements for each of `/`, `/posts/` and `/posts/hello-alnilam/` at the root and nested bases, with HTML and machine-readable JSON, CLS/LCP and complete resource/third-party audits. This bounded CNB route set intentionally excludes `/tags/` from the broader local Lighthouse config. The expected-red fixture uses the same `numberOfRuns` value as the baseline, and the evidence validator checks that count. Baseline assertions are advisory until observed. A separate severe-shift page must fail the CLS assertion with nonzero exit; missing reports or collection errors cannot count as that expected failure.

The trusted target Review job uploads its raw result and identity archive with a 14-day TTL. The untrusted browser job records its verdicts and platform identity in the build log but does not persist a browser archive: the previous native attachment attempt returned HTTP 403 because the untrusted token lacks the required write scope. No broader token or undocumented upload API is added. Browser artifact retention therefore remains unverified and is a consumer-acceptance blocker. Source SHA, target SHA, merge SHA, Site digest, runtime and timings accompany available evidence.
