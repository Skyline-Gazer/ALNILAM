# Issue #136 — Four-source differentiation and next-version proposal

**Status:** Draft for Owner decision. Issue #136 stays Open; this proposal does not modify `docs/ROADMAP.md`, create feature issues, or authorize implementation. The current Roadmap remains authoritative.

**Audit snapshot:** 2026-11-19. ALNILAM `dev` at [`e1d0174be5cda5996b39fb59737eca55782b5cc2`](https://github.com/Skyline-Gazer/ALNILAM/commit/e1d0174be5cda5996b39fb59737eca55782b5cc2). This is a source and evidence review; no upstream application was installed or run and no upstream source, asset, or dependency was imported.

## Product direction

Keep one frontend base: Shirone. Keep ALNILAM Core responsible for build and provenance, and the external Site responsible for user content and configuration. The Site remains read-only during builds. Prioritize dependable static publishing under both `/` and `/ALNILAM/`, accessible article reading, and optional content modules with explicit Site configuration. Do not add a second theme runtime or a hosted dependency to the core publishing path.

### Difference classification and decision summary

| Area | Difference class | Decision |
| --- | --- | --- |
| Home, article, gallery, Moments, comments, search | NOT APPLICABLE: this audit demonstrated no actionable upstream gap within the accepted scope; the route-specific evidence and limits above remain controlling. | KEEP the current ALNILAM implementation. |
| Music | PARITY GAP: upstream modules exist while ALNILAM does not expose an active player. This is an intentional scope gap under #69, not a release defect. | DEFER until #69's post-launch and Owner-acceptance conditions are met. |
| Friends/projects | PARITY GAP only if the Owner selects this capability; current product requirements do not require it. | DEFER; do not create a feature issue or port a showcase page from this audit. |
| Bangumi | DIFFERENTIATOR: ALNILAM fetches during build, retains a scoped last-valid result, and emits local covers instead of making visitor requests. | KEEP ALNILAM's implementation; require dedicated route evidence before claiming full acceptance. |
| Independent Site and provenance | DIFFERENTIATOR: the read-only Site input, schema contract, digest, staging, and rollback belong to ALNILAM Core. Upstream content-sync code does not replace this contract. | KEEP `scripts/compose.mjs` and Core/Site ownership. |
| Shirone 2.0.0 / Firefly source drift | UPSTREAM MAINTENANCE: 36 and 14 commits respectively since watch pins; no reproduced regression was established by commit count. | Propose an isolated compatibility study; import nothing until that evidence and separate Owner authorization exist. |
| Sample media and wholesale frontend replacement | DECLINED: repository assets do not establish redistribution rights, and a second theme/runtime would violate the selected single-frontend direction. | REJECT asset copying and full theme replacement. |
| Build/cache performance comparison | NOT APPLICABLE to a four-source product decision: no same-input upstream benchmark was run. | DEFER cache/storage policy to #145 and require reproducible workload evidence for any later performance claim. |

No BUG classification was established in this source review. A source path, an upstream feature, or a commit delta is not evidence of an ALNILAM bug.

### License and media boundary

Repository code licenses do not grant rights to sample photographs, music, fonts, or third-party artwork. Do not copy upstream content/assets into ALNILAM. Preserve existing notices and `SOURCE.json`; for any future code port, record the exact source path and SHA and retain the applicable license text. Mizuki's repository has both Apache-2.0 metadata and an inherited `LICENSE.MIT`, so the copied file's notice governs. Firefly's `package.json` omits a license field even though repository metadata is MIT. This audit made no copy, so it does not change `LICENSE`, notices, Site assets, or deployment output.

## Proposed next-version roadmap

Product goal: maintain a reliable, accessible, static-first publishing path with one Shirone frontend and immutable Site inputs; accept optional modules only when they meet a concrete user need and preserve root/subpath behavior. This is a proposal, not an adopted change to `docs/ROADMAP.md`.

| Priority | Work item | Dependency and authorization | Testable acceptance |
| --- | --- | --- | --- |
| P0 — current release readiness | Finish #74's field/manual acceptance and reconcile #42. Keep the current authorized launch scope. | Existing P6 work; no new feature authorization. | Record field p75 or mark unavailable with reason; complete manual screen-reader pass; retain root and `/ALNILAM/` browser evidence; update Project #17 only when each acceptance is met. |
| P1 — upstream maintenance proposal | Create a separate Shirone 2.0.0 compatibility study after Owner accepts this roadmap. Do not update the pinned runtime in this task. | Compare 36 commits since pin `55a84b2`; inspect each overlapping `SOURCE.json` modification; separate any implementation PR and obtain explicit scope approval. | Publish changed-path ledger; prove root/subpath install, build and browser parity on the current external Site; run existing `pnpm test`, `pnpm check`, `pnpm build`; compare bundle and build metrics on the same inputs; preserve licenses and rollback. | P1 — post-launch product feature | Music, tracked by existing [#69](https://github.com/Skyline-Gazer/ALNILAM/issues/69). | Only after first vNext production launch and Owner product acceptance, as #69 requires. | Disabled mode emits no player/provider request; enabled play/pause/track selection works; repeated route changes do not duplicate playback or listeners; test root and `/ALNILAM/`, keyboard and screen-reader names, reduced motion, and approved media rights. |
